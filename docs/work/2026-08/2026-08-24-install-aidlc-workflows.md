# 2026-08-24 — Install AI-DLC Workflows v2 (Claude Code harness), merged safely

## What changed
Installed `awslabs/aidlc-workflows` (v2 tag) into the repo for the Claude Code harness: `.claude/agents/` (14 `aidlc-*` role definitions), `.claude/skills/` (42 skills including the `/aidlc` orchestrator and per-stage single-stage runners), `.claude/hooks/`, `.claude/tools/`, `.claude/knowledge/`, `.claude/rules/`, `.claude/scopes/`, `.claude/sensors/`, `.claude/aidlc-common/`, `.claude/CLAUDE.md`, `.claude/settings.local.json.example`, plus the `aidlc/` workspace shell (sibling of `.claude/`, ships the method-tree memory the engine reads) and `.mcp.json` (context7 + 4 AWS MCP servers, optional/credential-gated). `.gitignore` got the AI-DLC per-machine/per-user runtime entries (session cursors, clone-id, journal scratch) appended. Installed `bun` (required runtime for every AI-DLC hook/tool) on the machine and added its PATH export to `~/.bashrc` so non-interactive Git Bash shells (what Claude Code's Bash tool actually spawns) can find it — a session restart is still needed for that PATH change to take effect in an already-running Claude Code process.

Deliberately **not** installed: the framework's own `.claude/settings.json`. It registers hooks on nearly every tool call (PreToolUse/PostToolUse on Read/Edit/Write/Bash/Task), forces `CLAUDE_CODE_USE_BEDROCK=1` with pinned Bedrock model IDs, sets `model: opus[1m]` / `effortLevel: xhigh`, and blanket-allows `Bash`. Applying it verbatim would have silently replaced the project's existing `enabledPlugins` (crew-kiro's `javascript-typescript`/`database-design`/`backend-api-security`/`cloud-infrastructure` plugins, active since 2026-08-11) and switched the model provider to Bedrock, which this project has no credentials for.

## Why
User request: "instala esto en nuestra rama" pointing at the aidlc-workflows v2 repo. This is the same AI-DLC methodology referenced throughout the org-wide meetings documented in Notion this week (Jean Carlo's 2026-08-18 session, and the 2026-08-20 "Ruta de Adopción" meeting) — Intelix is standardizing on it org-wide, with Kiro/Cursor as the IDE-side tools and AI-DLC as the methodology layer. Installing it here lets this branch try the same workflow already running for Mayoreo/EPA before it's mandated for Olo.

## How
Cloned `awslabs/aidlc-workflows` at the `v2` tag into a scratch temp dir (not inside this repo). Inspected `dist/claude/.claude/` first — confirmed every file/dir it ships is namespaced `aidlc-*` (agents, hooks, skills, tools, sensors, scopes, rules) except `CLAUDE.md`, `settings.json`, `settings.local.json.example`, and the parent `.mcp.json`, so there was zero filename collision with the existing crew-kiro installation. Copied everything except `settings.json` directly into `.claude/`, copied `aidlc/` to the project root as a sibling of `.claude/` (per the README's explicit layout), and copied `.mcp.json` (no pre-existing file, and the AWS/context7 servers it declares fail closed without credentials — additive, non-disruptive). Verified via `git status`/`cat .claude/settings.json` that the existing plugin config was untouched. Installed bun via the official Windows PowerShell installer, then confirmed via a fresh Bash tool call that the running session still couldn't see it (expected — Windows updates the User PATH registry key, but an already-running process's environment block doesn't pick that up, and Git Bash's non-interactive shell mode doesn't source `~/.bashrc` without `BASH_ENV`), so added the bun PATH export there per the README's own documented gotcha for exactly this Windows/Git-Bash combination.
